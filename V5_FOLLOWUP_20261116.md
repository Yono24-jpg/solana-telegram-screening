# v5 production follow-up, 16 November 2026

Production continued after initial deployment: eight subsequent successful scan runs were observed through 15:41 WIT. Telegram health remained a single sent message408; subsequent scans reported `not_due`.

## Defects found and fixed

1. The memory evaluator received a20-second sub-budget but immediately tested `deadline-20`. This skipped all observations. The legacy performance evaluator also received10 seconds while retaining a20-second reserve. New code evaluates already fetched quotes without external I/O, batches missing quotes20 pairs/request (up to60 per cycle), rotates failed attempts, records missed windows even without prices, and restores the original scanner deadline. Old prices are never backfilled as historic5m/15m observations.
2. Narrative extraction generated arbitrary CJK substrings and matched publisher names in headline suffixes. New code uses whole script runs or quoted names, removes publisher suffixes before matching, groups known multipart domain suffixes/subdomains conservatively, and excludes social/blog platforms and obvious download spam as independent-news corroboration. This is not a claim that publisher ownership or all misinformation can be verified.
3. Scheduler cooldown used a completed run's runner-start time ahead of creation time. Queue delays could therefore suppress an otherwise eligible next five-minute slot. Completed runs now use trigger creation time first. Active-run, shared cooldown and durable slot reservations remain mandatory.

No security thresholds changed. No candidate test messages or automatic trades are enabled. Existing bot, ON/OFF, secrets and Worker bindings are retained.

## Validation

213 Python regression tests pass locally, including eleven targeted evaluator/source regressions. Scheduler unit tests add two queue-delay/active-run regressions. Full Workers runtime, existing scanner and read-only live integration run in GitHub Actions before merge. The read-only audit uses a copy of public durable memory and can inspect due real observations without Telegram credentials or production writes.

Deployment/run/evaluation evidence will be appended after production verification. A successful workflow alone is not proof that every evaluator window has a fresh quote; observed and missed samples are reported separately.
